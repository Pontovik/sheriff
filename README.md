# sheriff

В городе новый шериф. Плагин для Claude Code, с которым Claude не срезает углы и не поддакивает.

У плагина два слоя:

- **Правила, всегда.** В начале каждой сессии Claude получает короткий свод правил работы с кодом: делать как принято в проекте, не раздувать задачу, не маскировать ошибки, писать тесты на намерение, а не на текущее поведение. На развилках он называет самое сильное возражение против выбранного пути, а если считает решение пользователя хуже альтернативы, говорит об этом прямо.
- **Режим шерифа, по команде `/sheriff:on`.** Claude ищет готовое решение в проекте до того, как писать код, и не может закончить ход, пока его правки не проверил независимый агент-ревьюер. Ревьюер видит замороженный дифф изменений сессии и проверяет его по рубрике: корректность, договорённости проекта, скоуп, структура, стиль, тесты.

## Требования

- Claude Code 2.1.281 или новее.
- Node.js 18 или новее в `PATH`: на нём работают хуки.
- Git для полного режима. Вне git работает урезанный режим.

Зависимостей npm нет, сеть плагину не нужна.

## Установка

В Claude Code:

```
/plugin marketplace add Pontovik/sheriff
/plugin install sheriff@razinkov-plugins
```

Для разовой проверки без установки, из клона репозитория:

```
claude --plugin-dir <путь к клону>
```

## Использование

Правила включены всегда. Скилл `/sheriff:debate` Claude вызывает сам на вопросы вида «как лучше» и «что выбрать»: отвечает с чёткой позицией и ценой каждого варианта.

Режим шерифа переключает только команда, набранная пользователем. Сам Claude её вызвать не может.

| Команда | Действие |
| --- | --- |
| `/sheriff:on` | Включить. Текущее состояние дерева становится базой |
| `/sheriff:off` | Выключить. Хуки молчат |
| `/sheriff:on --rebase` | Сдвинуть базу на текущее состояние |
| `/sheriff:on --from-head` | Считать изменениями всё, чем дерево отличается от HEAD |
| `/sheriff:status` | Показать состояние, ничего не менять |

После команды Claude цитирует строку `SHERIFF-MODE ...` от хука. Нет строки: режим не включился.

Как идёт ход во включённом режиме:

1. Claude правит код и запускает ревьюера `sheriff:reviewer` с брифом: задача, ограничения, принятые решения.
2. Плагин снимает снимок изменений с момента включения и передаёт ревьюеру дифф и рубрику.
3. Ревьюер пишет замечания и заканчивает отчёт строкой протокола `SHERIFF-REVIEW <снимок> COMPLETE`. Если строки нет, у него одна попытка её дописать, потом отчёт считается нарушением.
4. Claude чинит замечания и запускает ревью снова. Ход закончится, только когда текущее состояние файлов совпадает с проверенным снимком.

Ревьюер один на сессию и работает в переднем плане. Запуск из прошлого хода, оборванный пользователем, считается брошенным и следующему не мешает. Если Claude трижды подряд пытается закончить ход без ревью, предохранитель отпускает ход с предупреждением.

## Настройка проекта

Файл `.sheriff.json` в корне репозитория. Все поля необязательны.

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `ignore` | `*.md`, картинки, офисные и медиа-файлы, `LICENSE` в корне, файлы с секретами (`.env`, `*.pem`, `*.key`, `id_rsa*`, `.npmrc` и другие) | Шаблоны файлов, которые не требуют ревью. Дополняет список по умолчанию |
| `include` | пусто | Шаблоны файлов, которые требуют ревью вопреки `ignore` |
| `excludeDirs` | `.git`, `node_modules`, `bin`, `obj` и другие | Каталоги, которые не обходятся вне git. Дополняет список |
| `reviewTimeoutMinutes` | 30 | Через сколько активный запуск ревьюера считается оборванным |
| `unboundRunSeconds` | 15 | Через сколько незапустившийся ревьюер снимается |
| `lockStaleSeconds` | 60 | Срок брошенного лока состояния |
| `retentionDays` | 14 | Срок хранения данных сессий |
| `maxFileBytes` | 2097152 | Файл больше этого попадает в дифф заголовком без тела |
| `maxFileDiffBytes` | 102400 | Дифф файла больше этого попадает заголовком без тела |
| `maxPromptDiffBytes` | 204800 | Общий дифф больше этого передаётся ревьюеру путём к файлу. Независимо от настройки дифф идёт файлом, если вместе с данными ревью не помещается в 9000 символов |
| `noGitLimitMB` | 50 | Лимит суммарного размера влияющих файлов вне git |

Шаблон без `/` сравнивается с именем файла на любой глубине, шаблон с `/` с путём от корня. Ведущий `/` привязывает имя к корню: `/LICENSE`. Поддерживаются `*`, `**`, `?`, регистр не учитывается.

Всё, что не попало в `ignore`, требует ревью. Документацией по умолчанию считаются `*.md`, `*.rst`, `*.adoc`, а `*.txt` требует ревью: среди таких файлов `requirements.txt` и `CMakeLists.txt`. Файлы из `ignore` плагин не читает, поэтому секреты не попадают ни в снимок, ни к ревьюеру. Чтобы такой файл всё же проверялся, например `.env.example`, добавь его в `include`.

Настройки читаются при включении режима и при смене базы и дальше не меняются. Правка `.sheriff.json` посреди сессии начнёт действовать после `/sheriff:on --rebase`, а сам файл попадёт в ревью как обычное изменение.

## Ограничения

- Подмодули и символические ссылки плагин не читает. Изменение внутри подмодуля в ревью не попадает, плагин называет такой путь в предупреждении.
- Строки в диффе сравниваются без учёта окончаний. Смена только окончаний строк в файле, который был грязным до включения, считается изменением и помечается в диффе одной строкой.
- Файл, который был грязным до включения, не перечитывается, пока у него те же размер и время правки.
- Копии исходно грязных файлов ограничены лимитом `noGitLimitMB`. Сверх лимита, а также для бинарных файлов, хранится только хеш, и дифф такого файла идёт заголовком без тела.
- Защиты от намеренного обхода нет: агент с доступом к shell может стереть состояние плагина.

## Устройство

```
core/principles.md        правила, печатаются в контекст при старте сессии
core/review-rubric.md     рубрика ревьюера
hooks/hooks.json          события и таймауты
hooks/lib/state.js        состояние сессии, лок, журнал, уборка
hooks/lib/changes.js      база, кандидаты, изменения сессии, дифф
hooks/lib/diff.js         построчный unified diff, собственная реализация
hooks/lib/fs-walk.js      обход вне git
hooks/lib/config.js       .sheriff.json и значения по умолчанию
hooks/session-start.js    SessionStart: правила и состояние режима
hooks/mode-toggle.js      UserPromptExpansion: /sheriff:on, off, status
hooks/review-snapshot.js  PreToolUse(Agent): снимок и дифф для ревьюера
hooks/review-bind.js      SubagentStart: привязка ревьюера, данные ревью в его контекст
hooks/review-done.js      SubagentStop: результат ревью
hooks/review-failed.js    PostToolUseFailure(Agent): сбой ревьюера
hooks/require-review.js   Stop: блокировка без действительного ревью
skills/on, skills/off, skills/status, skills/debate, agents/reviewer.md
```

Хуки не разрешают вызовы инструментов и не меняют их вход, только отклоняют. Данные ревью доходят до ревьюера через контекст, который хук SubagentStart добавляет при его старте. Claude Code заменяет контекст хука длиннее 10 000 символов превью на 2 КБ, поэтому снимок и строка протокола идут первыми, а дифф и рубрика, которые не помещаются, передаются путём к файлу.

Состояние лежит в папке данных плагина, по папке на сессию. В репозиторий проекта плагин ничего не пишет.

## Тесты

```
node test/run.js
```

Тесты запускают хуки отдельными процессами с тем входом, который им передаёт Claude Code, на временных git-репозиториях. Поведение самого агента они не покрывают.

## Отладка

Переменная окружения `SHERIFF_DEBUG=1` пишет вход и выход каждого хука в `debug.jsonl` в папке данных плагина. Журнал последних 200 событий сессии лежит в `state.json`, поле `journal`.

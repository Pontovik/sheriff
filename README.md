# sheriff

В городе новый шериф. Плагин для Claude Code, с которым Claude не срезает углы и не поддакивает.

- **Всегда:** делает как принято в проекте, не раздувает задачу, говорит, когда не согласен.
- **После `/sheriff:on`:** ищет готовое решение до кода и не может закончить ход, пока правки не проверил второй агент.

Полное ТЗ: документ «ТЗ: плагин forge (v7)». Он написан до переименования: `forge` там это `sheriff`, `/forge:eng` это `/sheriff:on`.

## Требования

- Claude Code с событиями `UserPromptExpansion`, `SubagentStart`, `SubagentStop`, `PostToolUseFailure`. Проверено на 2.1.281.
- Node 18 или новее в `PATH`.
- Git для полного режима. Вне git работает урезанный режим.

Зависимостей npm нет, после клонирования сеть не нужна.

## Установка

Из локальной папки или из git-репозитория, две команды:

```
claude plugin marketplace add C:\Projects\sheriff
claude plugin install sheriff@razinkov-plugins
```

Для разовой проверки без установки:

```
claude --plugin-dir C:\Projects\sheriff
```

## Использование

Базовый слой включён всегда: принципы в контексте, строка возражения на развилках, позиция при несогласии, скилл `/sheriff:debate` на вопросы вида «как лучше».

Режим шерифа переключает только команда, набранная пользователем:

| Команда | Действие |
| --- | --- |
| `/sheriff:on` | Включить. Текущее состояние дерева становится базой |
| `/sheriff:off` | Выключить. Хуки молчат |
| `/sheriff:on --rebase` | Сдвинуть базу на текущее состояние |
| `/sheriff:on --from-head` | Считать изменениями всё, чем дерево отличается от HEAD |
| `/sheriff:status` | Показать состояние, ничего не менять |

После команды агент цитирует строку `SHERIFF-MODE ...` от хука. Нет строки: режим не включился.

## Настройка проекта

Файл `.sheriff.json` в корне репозитория. Все поля необязательны.

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `ignore` | `*.md`, картинки, офисные и медиа-файлы, `LICENSE` в корне | Шаблоны файлов, которые не требуют ревью. Дополняет список по умолчанию |
| `include` | пусто | Шаблоны файлов, которые требуют ревью вопреки `ignore` |
| `excludeDirs` | `.git`, `node_modules`, `bin`, `obj` и другие | Каталоги, которые не обходятся вне git. Дополняет список |
| `reviewTimeoutMinutes` | 30 | Через сколько активный запуск ревьюера считается оборванным |
| `unboundRunSeconds` | 15 | Через сколько незапустившийся ревьюер снимается |
| `lockStaleSeconds` | 60 | Срок брошенного лока состояния |
| `retentionDays` | 14 | Срок хранения данных сессий |
| `maxFileBytes` | 2097152 | Файл больше этого попадает в дифф заголовком без тела |
| `maxFileDiffBytes` | 102400 | Дифф файла больше этого попадает заголовком без тела |
| `maxPromptDiffBytes` | 204800 | Общий дифф больше этого передаётся ревьюеру путём к файлу |
| `noGitLimitMB` | 50 | Лимит суммарного размера влияющих файлов вне git |

Шаблон без `/` сравнивается с именем файла на любой глубине, шаблон с `/` с путём от корня. Ведущий `/` привязывает имя к корню: `/LICENSE`. Поддерживаются `*`, `**`, `?`, регистр не учитывается.

Всё, что не попало в `ignore`, требует ревью. Файлы `*.txt` по умолчанию тоже: среди них `requirements.txt` и `CMakeLists.txt`.

Настройки читаются при включении режима и при смене базы. Правка `.sheriff.json` посреди сессии начнёт действовать после `/sheriff:on --rebase`, а сам файл попадёт в ревью как обычное изменение.

## Ограничения

- Подмодули и символические ссылки плагин не читает. Изменение внутри подмодуля в ревью не попадает, Stop называет такой путь в предупреждении.
- Строки в диффе сравниваются без учёта окончаний. Смена только окончаний строк в файле, который был грязным до включения, считается изменением и помечается в диффе одной строкой.
- Файл, который был грязным до включения, не перечитывается, пока у него те же размер и время правки.
- Копии исходно грязных файлов ограничены лимитом `noGitLimitMB`. Сверх лимита, а также для бинарных файлов, хранится только хеш, и дифф такого файла идёт заголовком без тела.
- Защиты от намеренного обхода нет: агент с доступом к shell может стереть состояние плагина.

## Отличия от ТЗ v7

- Дифф строит собственная реализация в `hooks/lib/diff.js`, а не сторонняя библиотека в `hooks/vendor`.
- Ревьюеру даётся одна попытка дописать строку протокола, прежде чем отчёт считается нарушением.
- Привязанный запуск ревьюера из прошлого хода считается брошенным сразу, без ожидания 30 минут. Stop снимает запуск, которого нет среди фоновых задач.
- Настройки замораживаются в состоянии сессии при включении.
- `*.txt` требует ревью, документацией по умолчанию считаются `*.md`, `*.rst`, `*.adoc`.

## Устройство

```
core/principles.md        принципы, печатаются в контекст при старте сессии
core/review-rubric.md     рубрика ревьюера, хук дописывает её в его промпт
hooks/hooks.json          события и таймауты
hooks/lib/state.js        состояние сессии, лок, журнал, уборка
hooks/lib/changes.js      база, кандидаты, изменения сессии, дифф
hooks/lib/diff.js         построчный unified diff, собственная реализация
hooks/lib/fs-walk.js      обход вне git
hooks/lib/config.js       .sheriff.json и значения по умолчанию
hooks/session-start.js    SessionStart
hooks/mode-toggle.js       UserPromptExpansion для /sheriff:on
hooks/review-snapshot.js  PreToolUse(Agent): снимок и дифф для ревьюера
hooks/review-bind.js      SubagentStart: привязка agent_id
hooks/review-done.js      SubagentStop: результат ревью
hooks/review-failed.js    PostToolUseFailure(Agent): сбой ревьюера
hooks/require-review.js   Stop: блокировка без действительного ревью
skills/on, skills/off, skills/status, skills/debate, agents/reviewer.md
```

Состояние лежит в папке данных плагина, по папке на `session_id`. В репозиторий проекта плагин ничего не пишет.

## Тесты

```
node test/run.js
```

Тесты запускают хуки отдельными процессами с тем входом, который им передаёт Claude Code, на временных git-репозиториях. Покрывают сценарии раздела 12 ТЗ, кроме поведения самого агента.

Что проверено на настоящем Claude Code 2.1.281 под Windows: манифесты, скиллы и агент проходят `claude plugin validate`, хуки SessionStart и UserPromptExpansion срабатывают, их вход совпадает с тем, что подают тесты.

Что ещё не проверено вживую: цепочка PreToolUse, SubagentStart, SubagentStop и Stop с настоящим субагентом, установка двумя командами, запуск под Linux.

## Отладка

Переменная окружения `SHERIFF_DEBUG=1` пишет вход и выход каждого хука в `debug.jsonl` в папке данных плагина. Журнал последних 200 событий сессии лежит в `state.json`, поле `journal`.
